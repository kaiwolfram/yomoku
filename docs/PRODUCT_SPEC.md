# Yomoku product specification

**Yomoku** — *“Learn Japanese by reading”* A native, offline-first Android app
for reading Japanese books, text, and subtitles while
tracking vocabulary and reading progress. Inspired by Lute, but this is its own
product.

This is the authoritative product scope, behavior and required architecture.
It describes requirements, not implementation status. Confirmed requirements
must not change without user approval.

- [Architecture](ARCHITECTURE.md) and [data model](DATA_MODEL.md): implemented design and remaining boundaries.
- [Decisions](DECISIONS.md): technical decisions and dependency evidence.
- [Development](DEVELOPMENT.md): CLI setup and verified commands.
- [Agent workflow](../AGENTS.md): coding-session instructions.

## 1. Product scope and priorities

**v1 includes:** native Android app, native Japanese reader, local library of imported EPUB/TXT/SRT and pasted text, offline word segmentation and dictionaries, vocabulary status workflows, historical reading/vocabulary statistics, optional AnkiDroid integration, configurable settings, and release tooling.

**Important late scope changes that override earlier brainstorming:**

- **Remove statistics details and reading-time tracking** (user scope reduction, 2026-11-04): Statistics is an overview only; do not collect, persist or aggregate reading durations. Keep the two charts and existing timeframe filters.
- **Remove Known forms statistics** (user scope reduction, 2026-10-31): no separate Known surface/dictionary-form chart or dedicated dictionary-form aggregation storage. The five-status vocabulary chart still includes Known.
- **Feed/Nostr is no longer planned** (user scope reduction, 2026-11-02). Remove the Feed placeholder from phone bottom navigation and the tablet rail. No relay configuration/networking, post reading, signing identity, reactions or forwarding. Section 5 retains historical requirements only.
- **No custom dictionary entries in v1**: no editor, fallback definitions, saved custom records or custom-entry Anki export. Bundled dictionaries alone supply definitions; unmatched words show the no-match state.
- **No in-app AI features in v1**, including BYOK API keys/provider/model settings, AI-generated definitions or translations, and AI regeneration. Do not scaffold AI merely because older design notes might mention it.
- **Only EPUB, TXT, SRT, and pasted text**. No WebVTT `.vtt`, no ASS/SSA `.ass`, no PDF, no NHK integration, and no Android Share-intent import in v1.
- Nostr multi-device sync, Blossom cloud backups, and manual encrypted backup and restore are outside v1 scope.
- No full-text book search, no bookmarks, no editing of imported content, no in-app audio/video players, no custom goals or streaks, and no calendar heatmap.
- An online marketing site (possibly `yomoku.app`) is not part of the essential Android MVP. Concentrate on the app and tests first.

**Priority order:** dependable persistence / accurate reading and vocabulary semantics > robust imports / dictionary lookup > usable UI > charts > external integrations > release polishing. Do not start with Nostr, signing, or intricate UI styling before the local reader works.

- Library, Vocabulary, Statistics, and Settings content starts directly below the toolbar with no container top padding; retain horizontal and bottom spacing. Settings’ first heading has no extra top spacing.
- Loading feedback uses one accessible circular spinner in the top bar’s action area. In Library it replaces the **+** action in the same 48 dp slot only once visible, restoring the action immediately when loading ends. Aggregate storage, Vocabulary, Statistics, Anki setup/export and file-import activity. Show it after **300 ms of continuous loading**, cancel pending display when work finishes early, and hide it immediately on completion with no minimum display time. Screens and dialogs retain filenames, status/error messages, cancellation and disabled actions; horizontal loading bars are absent. Contextual circular indicators for individual Anki entries remain.

## 2. Required technical architecture

- **Android UI:** Kotlin with **Jetpack Compose**. Phone/tablet responsive layouts. Android min SDK **29** initially; reassess later if needed.
- **Domain/application logic:** Rust **Crux** core, ideally pure and testable without Android. Domain invariants and commands belong here.
- **Japanese analysis:** Rust **Sudachi.rs**, bundled **Sudachi Full dictionary**, one production reader using stored **Mode C with dictionary-backed import refinement** segmentation; A/B analysis is retained for dictionary components.
- **Offline dictionary data:** bundle **JMdict (English definitions)** and **JMnedict (names)** with the APK. Version them and satisfy redistribution/attribution requirements. Both sources appear in separate sections when both match.
- **Persistence:** SQLite, accessed from a separate Rust I/O/persistence layer using `rusqlite` / `tokio-rusqlite` as suitable. Keep SQL and Android-specific I/O **outside the pure Crux core**. Track schema migrations from the start.
- **Rust effects:** Rust-side `EffectRouter` executes Rust I/O. The first MVP has no Nostr networking. If Nostr is resumed later, networking belongs in Rust through **`nostr-sdk`**, not duplicated in Kotlin.
- **Android bridge:** Kotlin handles Compose, file picker, notifications/background execution, Android Keystore, AnkiDroid provider integration, and platform APIs; expose a narrowly scoped Rust FFI interface. Prefer explicit, typed state/actions over ad hoc strings.
- **Workstation workflow:** Gradle/Cargo CLI, terminal-based Android SDK/emulator/`adb`; **no Android Studio requirement** for normal build/test/run. Document native library build, ABI packaging, emulator setup, and release signing without committing secrets.
- **Repository:** MIT license for original code, respecting third-party licenses; clear module boundaries; local Rust/Kotlin tests, lint, and Android builds. CI/GitHub Actions is not required (user clarification 2026-10-27). Manual approval for signed publishing. Eventual APK distribution via GitHub Releases and Zapstore, not Google Play/F-Droid for initial publishing.

If a chosen library does not support a required capability or architecture in current versions, validate its actual API and explain the minimal deviation before changing a major architectural choice. Avoid blind dependency/version guesses.

## 3. Reader, text processing, and vocabulary behavior

### 3.1 Documents and pagination

- App opens on **Library**. Four main navigation items: **Library, Statistics, Vocabulary, Settings**. Settings is accessible only through the phone bottom navigation or tablet rail; keep navigation visible in Settings and remove toolbar and reader shortcuts to Settings. Settings has no toolbar back button; Android system-back behavior is unchanged. Hide main navigation while actively reading or pasting text.
- Reader is **horizontal text only**, single centered column even on landscape tablets; comfortable maximum text width, tablet margins. Dictionary panel on wide displays, bottom sheet on phones. Both portrait and landscape supported.
- Logical page length setting has **presets 250 / 500 / 750 / 1,000 characters**, default **250**. Existing saved preferences, including 500 and legacy 1,500-character values, remain unchanged without migration or automatic reflow. Count all non-whitespace Unicode characters, including punctuation and Latin text (user clarification 2026-10-22); supplementary characters count once. Split at a paragraph boundary after reaching the threshold; if a paragraph is extremely long, split after an appropriate following sentence. **Never cross an EPUB chapter boundary** when forming a logical page. TXT has no automatically inferred chapter boundaries.
- Logical pages may **scroll vertically**, e.g. for long text or images. **Never persist vertical scroll positions**: navigating forward or backward, or reopening a document, starts at the top of the destination page. Page boundaries don't depend on screen dimensions. Page-length changes reflow pages while preserving the exact underlying reading text offset.
- **Previous** and **Next** controls, with counter `12 / 85` between them, appear at the bottom of the page content. Naturally sized buttons align to the outer edges within the reader margins and tablet width limit; the counter remains exactly centered, including for **Finish Book**. Horizontal swipes do not navigate or complete pages. Use **Previous**, **Next**, or **Finish Book** to navigate. Both forward and backward navigation update the *current* reading position; the Library's percentage uses current text offset / total text length, so it can decrease if the reader goes backward.
- Long-press **Next** opens an anchored **Skip page** menu. Opening or dismissing it never advances. Skip saves the next logical page’s starting position and opens it at the top without occurrences, statistics, automatic statuses, completion notices, or changes to Library read status. Explicit status changes remain saved. Duplicate, stale, and busy actions are rejected; a failed position save keeps the current page visible and permits retry. **Finish Book** has no Skip action.
- Advancing **forward** completes the departing page. Simply moving **backward** does not complete or count the page. Reading a previously read page and completing it again **does count again** (idempotency must prevent accidental double-trigger/tap counting).
- Incomplete pages save position, **not** read-word events/counts/status updates until page completion. On page completion, every Japanese word occurrence (including repetitions) contributes to encounter/reading counts; any still-**New** unique words present on that page are changed directly to **Known**. Don't automatically change Learning/Familiar/Ignored. Show toast `N new words marked as Known` **only when N > 0**.
- Full-document completion records that the book has been finished and clears any manual Library read override. The Library then shows a checkmark. Reader pages have no checkmark. After confirmed completion, show a noninteractive upward fan of about 90 colorful confetti pieces from the **Finish Book** button’s center over roughly 1.6 seconds as the app returns to Library. Capture and retain the origin only in the current Compose session while saving; consume each command’s notice once, with no replay after recreation. If recreation loses the origin before confirmation, consume the notice without a celebration. **Finish Book** returns to Library. Reopening a book with a recorded finish begins at page 1 regardless of its Library read status. Deleting and later reimporting resets progress and checkmark, while global history survives.
- Reader toolbar title uses one line with an ellipsis and an accessible Back arrow. The page counter stays centered between equal-width controls, including Finish Book.
- While a book is open, remember the last tapped word occurrence independently on each logical page. Underline it with a 1 dp line in the text foreground color at 30% opacity, retaining vocabulary backgrounds and normal tap behavior. A new tap replaces only that page’s marker; returning to a page restores it across refreshed token revisions. Sheet dismissal and status changes retain it. Keep markers only in Compose memory: leaving the book, replacing the app session, or changing logical page length clears them; font-size and line-spacing changes retain them.
- Reader styling: bundled **Noto Serif JP**; adjustable global font size and line spacing; base text only, with no furigana setting or reading overlays. A settings button at the far right of the reader toolbar opens an anchored popup with the same typography controls as Settings. Keep it open during adjustments; dismiss with Back, an outside tap, or leaving the reader. Persist before publishing changes, show save failures, and allow another adjustment to retry. Typography changes preserve reading position, logical page boundaries, and token identity. Any delayed toolbar spinner sits immediately left of this button.
- EPUB supports chapters, headings, emphasis, inline images, and links, **but ignore EPUB CSS**. Recognize source ruby to retain its base text and discard reading annotations. Inline images keep position/ratio, fit column width; tapping opens full-screen pinch-zoom/pan viewer. Internal footnote/chapter links are **not navigable**; external website links open external browser. No TOC-jump feature.
- **Basic SVG image support is sufficient for v1** (user clarification 2026-10-27). Keep the existing bounded vectors/basic styles and self-contained embedded images. Complex SVG styling/resources (advanced stylesheet rules, patterns, masks, markers and additional resource loading) are outside v1 scope; unsupported images retain the alt/Retry or generic-cover fallback. EPUB page CSS remains ignored.
- Clipboard **Copy Sentence** was discussed but explicitly **deferred beyond v1**. Don't implement in first release.

### 3.2 Vocabulary model and dictionary panel

- Reader and Vocabulary share history wording: **Seen 5 times · 3 weeks ago**, with **time** for one occurrence. Reader includes occurrences on the current page; Vocabulary counts saved occurrences only. The date is the latest persisted completed reading of that exact written surface, including rereads and deleted documents, and excludes the unfinished page, popup taps, status changes, and skips. Omit the separator/date without saved reading. Relative times round down through just now, minutes, hours, days, weeks (7 days), months (30 days), and years (365 days); future dates display just now.

- Five globally tracked statuses: **New**, **Learning**, **Familiar**, **Known**, **Ignored**.
- Status colors: New blue (`#A9CCFF` light / `#28558D` dark), Learning light red (`#FFC5C0` / `#783E44`), Familiar yellow (`#FFE29A` / `#725A2D`), **Known unhighlighted in text** (green in graphs), Ignored pronounced gray (`#BEC5CF` / `#505B6B`). Word highlights inset each visible fragment by 1 dp on each horizontal side without altering text or tap ranges. Follow Android light/dark system theme; **no in-app manual theme override**.
- Vocabulary identity is the **exact written surface form**, NOT a lemma: `食べる`, `食べた`, `食べます` are separate entries with separate statuses and encounter counts. Same spelling with different readings is **one** status entry; show all appropriate dictionary readings/senses. Retain Sudachi dictionary forms where needed for dictionary lookup; no aggregate lemma statistics.
- **No manual correction of surface→dictionary-form mappings in v1** (complexity reduction). Do not edit bundled JMdict/JMnedict definitions or add user-created definitions. When bundled dictionaries have no result, show the existing no-match state.
- Default every newly encountered/imported written Japanese word to **New**. Upon **book import**, register **all unique word surfaces in its content immediately**, not lazily only when read. Deferred Nostr behavior: register vocabulary when a post is **first displayed**, even if it is later skipped. Registration is different from a **reading encounter**.
- Word tap opens dictionary UI with the original surface header and entries containing applicable readings/base forms, all **JMdict English senses immediately expanded and grouped by sense** without a redundant JMdict section heading, compact human-readable grammatical labels (e.g. noun, Ichidan/Godan verb, adjectives), and **JMnedict name readings/categories in a separate section** when available. Proper names are treated like other vocabulary, not excluded.
- Display **`Seen 47 times`** (saved lifetime completed-reading occurrences plus exact-surface matching visible occurrences on the current reader page, including rereads and repetitions; Vocabulary and Statistics use saved history only) for that surface. Opening/reopening the popup, repeated taps, rendering and status changes never persist or accumulate encounters; only page completion records them. Opening popup does **not** change status; use one visible **segmented pill with five direct status choices**, colored New blue, Learning coral, Familiar amber, Known green and Ignored gray. Clearly mark the selected section with straight interior edges and rounded outward corners only on the end segments; no increment/decrement controls. Tapping the selected status dismisses the panel without a status-change event; tapping another status persists it and keeps the panel open. There is no Close button; outside tap and system back also dismiss it. Omit standalone reading and dictionary-form header rows: dictionary entries supply those details.
- Reader and Vocabulary word sheets have a 12 dp copy icon beside the original surface header, with a 48 dp touch target and accessible **Copy word** label. Copy only the active part’s exact written surface, or the original surface when **Whole word** is active; exclude readings and definitions. Copy remains available during status saves and lookup errors, using Android clipboard feedback. **Whole word**, part chips and **More parts** keep their normal appearance during pending, failed and retried status writes while retaining disabled interaction and accessibility state. Status writes preserve the active part, expanded choices, definitions and sheet scroll position; actual dictionary lookups retain their normal loading feedback.
- New imports use **Sudachi Mode C followed by deterministic conjugation and counter joining** for highlighting, exact-surface vocabulary registration and completed-reading occurrences. Join adjacent verb/adjective stems, copulas (`だ`/`です`), and grammatical auxiliaries (including polite, negative, past, passive and causative forms), plus `て`/`で` followed by Sudachi non-independent helper verbs with lemmas `いる`, `ある`, `おく`, `しまう`, `みる`, `いく`, `くる`, `くれる`, `もらう`, or `あげる`; helpers and endings may repeat. For example, `できません`, `食べました`, `高くない`, `食べている`, and `食べてしまった` each form one highlighted surface. Use POS/conjugation metadata and exact source adjacency; stop at whitespace, punctuation, sentence boundaries, other particles, and independent words. Keep nouns before copulas separate (`学生` + `だった`); standalone non-copula auxiliaries and ordinary lexical helper uses retain their boundaries. Also join a numeral immediately followed by a grammatically tagged counter suffix, using POS tags and exact source adjacency without word lists (for example, `ひとつ`, `ふたつ`, `みっつ`, `一つ`, and `二個`); following particles and ordinary nouns retain their boundaries. Preserve the exact source surface/span and concatenated analyzer readings only when every part has one. Conjugations retain the head’s dictionary form; joined counted expressions use their complete surface as the dictionary form so lookup does not inherit the numeral’s meaning. After joining, retain any C token whose exact surface or analyzer base form occurs in JMdict or JMnedict. Otherwise try finer B components, keeping dictionary-backed larger components and refining unmatched B components with A. Replace C only when matching components cover its complete contiguous source span; an unmatched component retains the whole original token. Thus `制服姿` becomes `制服` + `姿`, while dictionary-backed compounds and conjugations remain intact. Apply this to new EPUB, TXT, SRT and pasted imports with payload-free membership queries on the I/O worker and a cache scoped to each import. Load required assets after input validation and duplicate detection, before the import transaction; dictionary failures fail the import atomically. Version this import policy and record the pinned word/name dictionary identity in the analysis profile; existing books keep immutable boundaries/history and support lazy raw A/B dictionary components under their original profile. Deleting and reimporting explicitly adopts the new profile with the existing progress-reset behavior. There is no manual boundary editing. The dictionary panel initially shows only applicable whole-token and base-form entries. Compact selectable suggestions beneath the original surface header offer proper contiguous dictionary-matching parts and finer A/B components with matching analyzer-supplied base forms, including names. Initially show parts not contained within a larger matching part; **More parts** reveals shorter overlapping matches. Order longer parts first, breaking ties by source position; deduplicate written surfaces at their earliest exact occurrence and retain analyzer base forms and offsets. Choosing a part replaces definitions and marks that choice selected; choosing the active part does nothing. **Whole word** restores initial results. Reopening starts with the whole word. Selection is disabled during lookup; failures offer explicit Retry for that same choice, and stale responses after another choice, dismissal or navigation are ignored. No free-range selection is added. Fetch definition payloads only for the active query; dictionary-index prefix pruning bounds discovery on long tokens. Status, encounters, reader highlighting and Library distributions remain attached to the original joined C surface; status changes preserve the chosen part and results. Anki observations and actions belong to the active lookup revision and individual dictionary entries.
- Custom dictionary entries are excluded. When bundled dictionaries have no result, show the no-match state.
- Show a small star in the theme’s purple primary color labeled **High priority entry** beside qualifying JMdict headword/reading pairs, independently of Anki setup. Priority uses `ichi1`, `news1`, `gai1`, `spec1` or `spec2`; a written pair must share a qualifying tag in its spelling and reading, while kana-only pairs use reading tags alone. Do not inherit priority from other forms or reorder results.
- No preknown vocabulary list. Nothing is implicitly Known from parser import, dictionary lookup, or Anki export.

### 3.3 Imports and library

- Supported **EPUB, TXT, SRT**, and **Paste Text**. Imported source content is **immutable**; users may rename but not edit. To change text, delete/reimport.
- Import book first requests Android 13+ POST_NOTIFICATIONS when missing, directly through the system prompt. Grant, denial or an unavailable runtime prompt then opens the existing picker; granted permission and older Android versions open it directly. Guard duplicate launches and stale callbacks; retain in-flight intent across activity recreation only, never process death. Notification permission controls visibility and does not gate foreground-service startup. Android picker selects **one book at a time**; cancelling the picker leaves application state unchanged. Each import is **atomic**. Detect an **exact duplicate with SHA-256** and reference the existing document instead of creating another copy. Upon new import register all unique surface forms as New without overwriting already existing statuses.
- Titles: EPUB metadata where present, otherwise filename; pasted text uses first line as initial title; user can rename.
- Preserve extracted reader content and the SHA-256 digest of the input file. Discard the input bytes after import. If an EPUB spine repeats a manifest item, import it once at its first position and skip later references.
- Android file acquisition admits at most the smaller of 256 MiB and one eighth of currently available Java heap (maximum heap minus used heap). Check actual bytes, regardless of provider size metadata, and check transport headroom again before native submission and each encoding retry, including filename/typed-field overhead. Reject over-budget files with a concise terminal memory error and allow another import. This bounds acquisition/transport; native parser limits still apply separately.
- Cancelled file acquisition stops at the next checkpoint around provider metadata/open calls and each bounded read. A provider may ignore interruption of an outstanding call; cancellation and a fresh import must not wait for it or its resource cleanup. Close obsolete cursors/streams on their reader worker and ignore their late progress, errors and submission callbacks.
- TXT: UTF-8 and Shift-JIS; attempt appropriate detection and allow manual selection when uncertain. Preserve original hard line breaks; no reflow of adjacent lines. Parse **common Aozora Bunko markup**, including ruby `｜漢字《かんじ》`, and hide/interpret common typographic directives. Don't infer chapters from titles such as `第一章`.
- SRT: best-effort parsing of mildly malformed files; strip timestamps/cue numbers and formatting tags (e.g. `<i>`), retain **separate cue blocks**, breaks within cues, and sensible spacing; do not merge successive cues into prose. Preserve speaker indications when meaningful. No VTT or ASS support in v1.
- Show the current filename with the shared indeterminate top-bar spinner, without file counts; permit **Cancel** to discard an uncommitted import. A successful commit wins a cancellation race. Retain encoding selection and retries; there is no Skip File action. Continue imports on Android while user opens another app when permitted by OS background policies; show progress/completion notifications when permission is granted, refreshing notification state on app entry. During normal progress the import dialog shows only the filename and Cancel. Retain encoding selection, cancellation feedback, and concise duplicate/error results; omit notification availability and background-limit paragraphs. Completion notifications are suppressed while an Activity is visible, including across recreation; background results keep their existing notifications. There is no notification-enable button or replacement permission prompt. If Android kills the process, **keep committed imports but do NOT automatically resume** the unfinished import on next launch. Do not misrepresent OS guarantees.
- After a newly created file import, close the import dialog without a success result. Preserve duplicate notices and errors in the import dialog and return to Library; **never automatically open reader**.
- Library: compact list with EPUB cover thumbnails (cache) or generic TXT/SRT/paste icons; title, current progress, a checkmark labeled **Read**, and a **stacked five-status distribution bar of distinct word surfaces present in that document** (not token frequencies), updated whenever global statuses change. The top bar has a **+** menu for **Paste Text** and **Import book**. No Library search or inline import-summary area (including success/duplicate messages and Close). Retain file-import dialogs, notifications, and errors. Active import dialogs and foreground progress notifications say **Importing book...**; cancellation, encoding-choice and completion wording remain distinct. The Library container has horizontal and bottom spacing but no top padding; sorting sits directly below the toolbar when no errors are present. With two or more documents, show sorting by last read (default), title, or import date with an ascending/descending arrow and a control to reverse the order; preserve the selected order below that threshold. Show new/unopened sensibly. The empty state centers a book icon, “No documents yet”, and “Tap + to import a book or paste text.” horizontally and vertically beneath status messages; message and hint use the Material `onSurfaceVariant` color. No folders/collections.
- Long-press a document for **Rename**, **Mark as read** or **Mark as unread** (depending on the checkmark), and **Delete**. Selecting the read action closes the menu. A confirmed save changes only the checkmark. A failed save shows the Library storage error and the same action remains available. Manual marking preserves reading position, reopen behavior, reading history, and sort order. There is no multi-selection or inline action button. Delete individually with confirmation; **no Undo**. Deleting removes content/current position and preserves source metadata needed for historical event provenance, historical reading stats, encounter records, and all global vocab statuses. If reimported later, treat as a **new document starting at 0%**, no restored completion checkmark.

## 4. Statistics, durable history, and vocabulary browser

### 4.1 Events and statistics

- Design schema around immutable, dated **status-change events**, **reading-completion events**, **every Japanese surface occurrence encountered on completed pages/posts**, and source identity/provenance. History matters more than cached counters; use migration-safe IDs and explicit versioned semantics.
- Multiple occurrences of a word on one completed page count multiple times. Re-reading counts again. Avoid duplicate counting on accidental repeated click/gesture. Non-Japanese content and punctuation aren't included in Japanese word counts.
- Statistics: one overview with two charts; no detail pages or drilldown actions. Timeframes in a compact dropdown showing the selected interval: **last week (default)**, **last month**, **last quarter**, **last year**, **all time**; group **daily / daily / weekly / weekly / monthly** respectively. Last quarter starts three calendar months before today in UTC, clamping to the target month’s last day; weekly buckets retain lifetime cumulative values. The compact selector has a rounded outline, balanced padding and a downward chevron. Last week includes today and the preceding six UTC dates, through the supplied current instant. Persist the selected timeframe across restarts and show it on entry. Selecting an interval closes the menu and preserves the screen’s vertical position.
- Graph 1: **cumulative lifetime Japanese word occurrences read**. Time filter changes visible x-range but **not** origin of cumulative y-values (e.g. 85k→100k for last month).
- Graph 2: **five distinct time-series lines** of absolute number of registered word surfaces in each status, with statuses' graph colors; import-time registration causes jumps in New.
- There are **two charts only**: cumulative reading occurrences and the five vocabulary statuses. No separate **Known forms** chart or distinct dictionary-form count. Keep the Known status line in Graph 2 and dictionary-form metadata required by reader/dictionary/history workflows.
- No calendar heatmaps, goals, streaks, or per-source charts in v1 (keep source identities internally).
- Vocabulary entries cannot be deleted through the app. Document deletion preserves vocabulary and its encounter/status history. Previously deleted vocabulary is not automatically recovered.

### 4.2 Vocabulary browser

- Separate top-level **Vocabulary** screen.
- Search by **written-surface prefix** only, indexed; no reading/lemma/full-text search.
- Default sort newest registration first; alternatives frequency, last seen, alphabetical. The arrow reverses the complete ordering; choosing a criterion restores its default direction (descending metrics, ascending alphabetical).
- Filter by five statuses in one horizontally scrolling row, preserving status order. Initially no statuses are selected; empty and all-five selections both match every status, while partial selections match only those statuses. Retain filter choices for the app session. Show total matching count; query 100 at a time with infinite scroll.
- Search scrolls with the list, above filters, sorting and matching count. During a sort change with the same search/status filters, keep the last successful rows and matching count visible and disable row interaction until the new results replace them together. Clear retained sort presentation on errors, search/status filter changes, or session changes. Use only the shared delayed toolbar spinner for loading feedback; no immediate Vocabulary loading text. Pagination always uses authoritative query results.
- A word tap opens the shared Word sheet, where individual status changes persist directly and record status events. Long press has no selection action. There are no selection, bulk status or vocabulary deletion controls.
- Vocabulary uses the reader's surface header, encounter count, expanded definitions/readings/grammatical labels, separate names, priority markers, and five-status pill. Anki actions are available beside each applicable dictionary entry, using the verified setup from Settings; Vocabulary exports leave the sentence field empty and require no source book. Analyze the exact saved surface temporarily with the bundled analyzer/profile, independently of source passages or book availability; use the same whole-word/part suggestions, replacement definitions, ordering, retry and reopening behavior as Reader. Lookup never registers words, persists analysis, records encounters, or changes status.
- Choosing another status persists immediately without confirmation and keeps the sheet open, including when the word leaves the current filter. Choosing the current status, outside tap, and Back dismiss. Successful writes that retain filter membership patch the affected row directly without clearing rows, reloading pages or repeating dictionary lookup. When membership changes, retain the visible list while refreshing its entire loaded prefix through paginated reads, then replace rows, matching count and authoritative pagination together. Preserve the first visible word and pixel offset; if it disappears, anchor its next surviving neighbor, or the previous neighbor at the end. Keep the open word sheet and its dictionary results, preserve exact retry payloads, and leave the list unchanged after failed writes. All successful writes invalidate Statistics, Library distributions, and retained reader statuses. Lookup failures require explicit Retry; failed status commands retain their original ID, status, and timestamp for Retry or Cancel, even after sheet dismissal. Ignore stale lookup responses after dismissal or navigation.

## 5. Historical Feed/Nostr requirements (no longer planned)

Feed/Nostr is no longer planned. Neither phone bottom navigation nor the tablet
rail exposes a Feed placeholder.

The following Nostr requirements are retained as historical reference only;
they must not drive implementation unless the user explicitly reopens this scope.

- Use Rust `nostr-sdk`. Fetch only **kind-1** text events from **explicitly enabled/curated author npubs** across enabled relays, with editable lists and add-custom options. **Never sample arbitrary relay authors**. Filter candidate post text **locally** for Japanese with lightweight hiragana/katakana + kanji heuristics; accept occasional inaccuracies. Hardcoded starter author/relay lists are a product-data decision: **do not invent accounts or relay endpoints; ask if no actual curated list is supplied**, or use a clearly empty/configurable list initially.
- One full post at a time; no social feed, no long-form kind 30023, no repost kind 6. Replies posted by curated authors may appear with reply indicator. Offer **View Parent** for immediate reply parent (fetch parent on demand if needed); deeper navigation is on demand. Just viewing parents must not create reading stats.
- Newest-first, **no age cutoff**; previously read and skipped posts are eligible again. An active queue holds **10** events (current + 9 prefetched); retain up to **20 previous** posts in memory. Keep queue stable if new events are published while user reads.
- On entering Nostr, fetch latest posts. Switching app tabs **within same process** resumes the current post/queue; background refresh should not interrupt it. Explicit **Refresh** begins a new latest-first queue. Full app restart **does not preserve queue/current post**; start fresh.
- Relay failures are nonblocking: show posts from available relays, unobtrusive warning, retry on next refresh. Deduplicate same events across relays.
- Display author's **name + avatar** from kind-0 profile metadata (fallback shortened npub/generic avatar) and **relative publication time**. Names, avatars, `npub` and `note` references are **not clickable**; standard external HTTP(S) links open in browser.
- Display every long post fully, vertically scroll if needed; **no Read More**, no content-warning gate, no separate kind-5 deleted-post filtering for *other people's posts* in v1. Non-Japanese parts of mixed posts display subdued, are not tappable vocab, and don't count as Japanese reading.
- Inline remote images load **when the post is displayed**, not during prefetch; placeholder while loading, **250 MB disk LRU** image cache; image taps use same full-screen pinch-zoom/pan viewer as EPUB. Audio/video show **Open Audio/Video** and open externally; no in-app player.
- Advance via **Next Post** or reading swipe, completing the post: record occurrences/time, change displayed still-New words to Known, and attempt forwarding **the original signed Nostr event** to an optional local Citrine-compatible relay. **Skip is an explicit button only**; Skip must not affect stats, statuses, or Citrine forwarding. Previous does not count completion. Never silently treat a swipe as Skip.
- Optional local relay (such as Citrine) can provide offline access to forwarded originals; the Yomoku database does **not** persist all external event bodies. Exact forwarding failure/retry policy is **UNRESOLVED Question 188**: ask user **A: queue forward attempts for retry vs B: best-effort no queue** before implementing this piece. Do **not** assume an answer.
- Automatically generate a random **12-word BIP39 mnemonic** on first launch, derive a Nostr signing key via NIP-06, store it encrypted at rest using Android Keystore, include it in the encrypted manual export. No login/signer UI.
- Heart reaction publishes Nostr kind-7 `+` to all enabled relays; removing own reaction uses a NIP-09 kind-5 deletion event, distinct from ignoring deletion filtering for other authors. **Optimistic UI** and persistent offline **reaction publish queue** for retry on connectivity return; no reaction counts, only own reacted/not reacted state.

## 6. AnkiDroid integration

- Only when AnkiDroid is installed and its supported ContentProvider integration is available; app works fully without AnkiDroid.
- **Check AnkiDroid** in Settings requests missing database permission and continues setup after approval, without another tap. Deck selection remains explicit, with 4 dp gaps between rows, 8 dp between radio buttons and labels, and full-row selection with minimum 48 dp touch targets. The check button keeps its position and text color while saving and verifying, remaining disabled for interaction and exposed as disabled to accessibility until work finishes. A successfully saved default deck, or an explicit check with an existing default deck, checks and creates the Yomoku model if missing. Compatible models are reused; incompatible or partially created models remain errors. One check button provides explicit retries; there are no separate permission/model-check/create buttons. Configuration authorization stays in memory, belongs to that setup request and deck, and is never restored or replayed after restart. Routine app-entry checks are read-only.
- Configure AnkiDroid permission, the default deck and the built-in **Yomoku** HTML/CSS note model in **Settings only**. Preserve existing models and cards. Once setup is verified, in reader and Vocabulary word sheets show a small **green + button beside each applicable dictionary headword/reading pair**; one tap adds that entry with the lowercase `yomoku` tag. Existing duplicate notes remain untouched. Status changes retain the selected word’s duplicate observations and lookup-request ownership through pending, successful, failed, and retried writes and transient sheet recomposition; they never trigger another Anki query or replace settled action icons with spinners. New lookup, app return, explicit retry, and insertion retain their existing refresh behavior. No Anki setup or export editor appears in the word sheet.
- Check duplicates by the entry’s **exact written headword and kana reading**, across models/decks when supported, including notes created elsewhere with an identifiable `Reading` field (case-insensitive field name). Notes without a verified matching reading do not block adding. Do not split multi-reading fields or normalize written forms/readings. Show a **pink button with a blue book icon** for existing notes; it opens AnkiDroid’s browser filtered to the verified note IDs. Check on lookup, after returning from Anki, and again before insertion. Failed checks must never imply absence.
- The model is unversioned. There are no legacy model definitions, compatibility paths or migrations; existing AnkiDroid notes/models are not automatically changed or deleted.
- Front: **the dictionary headword only** (kana for kana-only entries). Back: the selected kana reading, dictionary source, numbered applicable English senses ordered as translation, italic grammatical/usage labels, then sense notes (for both word and name entries), and, for reader exports, the original Japanese sentence with the matched source occurrence highlighted. Vocabulary exports have an empty sentence field. This ordering applies to newly exported notes; existing notes and card models remain untouched. The source can be inflected, e.g. 食べた for 食べる; selected-part highlights use the retained exact occurrence and offsets, including inflected analyzer components. Use compact readable light/dark styling. Add and book buttons have a 32 dp visible background, 16 dp icon and 48 dp touch target. **No audio**. Export does **not** change Yomoku vocabulary status.
- Export preparation, fresh query results and active-operation ownership remain in memory. Repeated taps and stale callbacks cannot submit an active operation twice; navigation does not retarget it. Revalidate permission, deck and model before writes, and refresh exact-headword-and-reading queries on lookup, returning to the app and immediately before insertion. Failed or incomplete queries remain errors. After interruption, perform fresh queries before an explicit retry; never replay a write automatically. There is no durable recovery or exactly-once guarantee across process death. An interrupted write may have completed partially; subsequent actions depend on fresh AnkiDroid observations. Never overwrite an incompatible or partially created model.

- Confirmed AnkiDroid insertions show `Added to AnkiDroid.` once. Duplicate, failed or uncertain results do not show success. App toasts replace the current toast; transient notices are consumed before display.
